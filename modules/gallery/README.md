# WorkBonny Gallery module

本模块由 WorkBonny 仓维护，完整前端、Rust、权限、测试与 MIT 许可证均在本目录。当前不发布 npm 或 Cargo 包；以后可整体拆出。应用只在 src/gallery.tsx、src-tauri/src/lib.rs 和 build.rs 接线。Rust 以应用内模块编译，权限由 Tauri InlinedPlugin 注册；保留独立 Cargo 清单供模块测试和未来拆出。模块不导入 WorkBonny 业务代码，宿主通过 GalleryHost 注入能力。

MIT-licensed Rust implementation and React UI. No private ALwith library, service, account or model required. Hosts register the Tauri gallery, dialog and opener plugins and mount `Gallery` with `createGalleryHost()`. Import `./modules/gallery/src/styles.css`. The gallery does not own or create a window; it fits in an Atlas page or any sized container.

Select a folder using the native picker. Supported formats: JPEG, PNG, WebP, GIF (first frame), BMP, TIFF. Subdirectories are included; symbolic links are skipped. HEIC, RAW and SVG are not supported. Filename, size and modification time come from the filesystem (not invented EXIF dates). Previous folder and selection are remembered. The native watcher reports changes; the explicit Update action rescans once. No automatic retries or uploads.

Five strips sample one image automatically; hover aligns their vertical offsets. Slice mode fits the entire image at its original aspect ratio inside the available space (allowing for the four gutters and vertical offsets); portrait images remain portrait. Original appearance contains the whole bounded preview. Clicking the artwork or pressing Space on the gallery opens macOS Quick Look; Windows uses the default image application. There is no in-app enlarged-image dialog. Arrow keys and compact previous/next controls select images. The main exhibition has no thumbnail strip. Browse all opens a searchable grid (48 entries per page); thumbnails load near the visible area and are released when it closes. One low-priority next-image prefetch warms the native preview cache. Original files open in the system application. The preview is at most 2560px; thumbnails at most 240px. Original images are never modified. Files above 128MiB, dimensions above 32768px or above 64MP are rejected; decoding uses a 256MiB allocation limit. One decoder runs at a time; the frontend prioritizes previews over queued thumbnails and cancels obsolete queued work. Each native decode creates both preview and thumbnail. A bounded in-memory Blob cache makes revisiting recent images immediate; the JPEG derived cache is capped at 256MiB and invalidated by path, size and modification time. Cache eviction is oldest-write first. A folder is limited to 20,000 supported entries and 32 subdirectory levels. Errors remain visible, not retried.

Source and build instructions are included in the npm archive. `bun run build`, `bun run check`, and `cargo test --manifest-path rust/Cargo.toml`. Rust crate has its own workspace and uses public registry dependencies only. `workbonny-gallery:default` grants gallery commands to selected host windows. The native picker establishes the readable root, every image access canonicalizes within it, and stale album revisions are rejected. This grant is not an OS sandbox against malicious concurrent filesystem mutation.

Current lifecycle: native watchers belong to their webview and are released by close/window destruction. React releases object URLs on selection changes/unmount. A decode already running is bounded but not preempted. Large-library scans currently run to completion on a blocking worker. Accessibility includes keyboard controls, focus rings and reduced-motion support. No published release or full platform acceptance is implied by this local candidate.
