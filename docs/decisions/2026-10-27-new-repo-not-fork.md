# workbonny 是新仓，不 fork ALwith U

日期：2026-10-27。状态：已拍板。

## 问题

要做"客户 WorkBuddy"的实例，起点是 fork alwith-u 还是空目录。

## 决定

空目录新仓。U 与 workbonny 是两个同级消费者，共享的东西全部进包；好东西回 U 的路径永远是"先进包，U 再装"，从不直接从 workbonny 搬代码到 U。

## 为什么

| fork 的问题 | 现象 |
| --- | --- |
| 验证不了任何东西 | 验收问的是"外人凭发行物能不能做出来"，fork 是把答案抄来改名，一小时时限、文档缺口、壳模板缺口全测不到 |
| 掩盖最大的缺口 | U 的品牌硬编码，fork 后第一件事就是满仓改 productName、identifier、locales，这正是该上游解决的事 |
| 长成第二个 U | fork 带着 U 全部 Rust 模块和 feature 走，重复 TV 从 Desktop 分出来后两套实现互相追的路径 |

U 的 AGENTS.md 已定"同级应用共享的东西必须抽成包，禁止复制"，新仓只是让这条规则有了执行者。

## 代价

从 U 复制单个文件允许，但每复制一个要在缺口台账记"X 本该是包"，验收时该文件必须已被包替代并删除。U 是 Apache-2.0，法律无碍，约束只为验收不失真。
