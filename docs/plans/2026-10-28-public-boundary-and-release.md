当前范围整理：2026-11-01。总体目标见[总计划](2026-10-27-own-workbuddy.md)，缺口与证据见[台账](../gaps.md)。

## 交付约束

开发、联调与验收使用隔离的本地候选包，不以发布作为调试前提。全部实现和兼容性验证完成后集中发布受影响包，再更新正式依赖及锁文件；不边改边发。create-alwith 新版本继续暂停发布。

create-alwith 使用 ALwith-ai 的独立公开仓，按 AGPL v3 交付。应用只能依赖公开发行物；混合仓可见性不能代替包内容和来源检查。本计划不新增公开仓库、变更许可或授权操作，也不把过去的临时发布操作作为长期流程。

公开 npm 包包含的 Rust SDK、DTO 或桥接源码，其依赖解析必须留在发行物内；不能反向依赖私有实现或维护者路径。不为公开／私有边界把包拆碎，不新增运行时交付机制。

## 联合验证

| 消费者 | 验收重点 |
| --- | --- |
| U | 标准聊天、账号、项目与活跃会话、菜单、设置和创建入口 |
| TV | 共享 chat/auth 与原生机制兼容，保留原版画板布局，不新增侧栏 |
| WorkBonny／生成项目 | 默认共享实现完整，无应用自建替代样式；两种账号模式、双品牌、独立构建与运行 |
| Desktop | 共用 shell 机制与状态呈现，保留明确的定制底栏与缩略图入口 |
| GitCub | 共用适用壳机制，底部 16、不装底栏与分页 |

公共协议同时考虑 Codex 与 alwith-cli；Codex projectId 不强加给其他引擎。ACP 能力和 metadata 属适配器，API 只做 Runtime 公共封装。

验证覆盖启动、刷新、关闭、重启、状态订阅释放及各实际入口。当前先验 macOS；Windows 实机暂缓。不把真实认证、模型会话或未测平台记成已验证。

## 发布前后证据

发布前核对候选集合、依赖闭包、许可、包内容、生成器锁文件和受影响消费者。发布后用正式发行物重新生成、冻结安装、锁定构建并检查独立性；候选验证不能替代这一步。源码提交、远端推送、npm 发布、依赖接入和实机运行分别记录，不互相冒充。
